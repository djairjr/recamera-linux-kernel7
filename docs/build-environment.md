# Build environment and project map

**Rule:** everything that goes to the camera comes out of `container/run.sh make ...`
or out of a script in `scripts/` that builds inside the container. Nothing is made by
hand, kept in `/tmp`, or left in loose folders outside the tree.

## 1. Project map

| Path | What | Made by |
|---|---|---|
| `container/` | Docker image of the toolchain (`Dockerfile`, `sdk-defconfig`, `patches/`) and `run.sh` | source |
| `buildroot/` | Buildroot 2026.05.3 (git submodule) | pinned |
| `external/` | the project's br2-external: `configs/`, `board/`, `package/`, `patches/` (kernel) | source |
| `external/package/sophgo-*` | Sophgo ports to Linux 7.2: `ion`, `osdrv` (kernel modules), `mpi` (userspace), `cviruntime` (NPU) | patches regenerated by `scripts/port.sh` |
| `external/package/recamera-fip` | the boot `fip.bin`, checked in (§5) | prebuilt |
| `external/package/recamera-firmware` | Wi-Fi/BT firmware, sensor tuning, NPU kernels, downloaded from pinned URLs with sha256 | the package |
| `external/package/morse-*`, `wpa-supplicant-s1g` | Morse Micro Wi-Fi HaLow driver, CLI and `wpa_supplicant` (1.14.1) | the packages |
| `external/package/recamera-tests` | the port's check programs (`recamera-iontest`, `-ioninfo`, `-fencetso`) | the package, from `tests/` |
| `tests/` | sources of the check programs | source |
| `app/` | the Rust application: Cargo workspace, MIT/Apache-2.0; `Cargo.lock` versioned | source; package `recamera-app` |
| `scripts/` | deployment, ports, models, diagnostics (§4) | source |
| `docs/` | documentation | source |
| `output/` | Buildroot output (`images/`: `sdcard.img`, `rootfs.ext4`, `boot.itb`, `fip.bin`) | `make` |
| `dl/` | Buildroot downloads | `make` |
| `.ccache/` | compiler cache (§3) | `make` |
| `work/` | scratch areas: ports (`work/<package>/a,b,build`), models (`work/models/`), Rust target | `scripts/` |
| `local/` | files of one installation, never versioned (`local/wpa_supplicant.conf`, §9) | by hand |

Not versioned (`.gitignore`): `output/`, `dl/`, `.ccache/`, `work/`, `local/`, and any
model weights.

**Outside the tree, optional:** the official Seeed 0.2.4 release files (images, factory
rootfs). `container/run.sh` mounts the directory `RECAMERA_OFFICIAL` (default
`../oficial`) read-only at `/official` when it exists; only `scripts/models.sh extract`
uses it.

**Not needed:** the Seeed SDK (reCamera-OS, 16 GB with its submodules). Every vendor
source the build uses is downloaded by its package at a pinned commit (the pins of
reCamera-OS 0.2.4, listed in `docs/vendor-pins-0.2.4.md`). Only two developer tools
want a checkout of it: `scripts/port.sh` (`RECAMERA_OS=`) and
`external/package/recamera-fip/make-fip.sh` (`SDK=`).

## 2. The toolchain image (`container/`)

- **`container/Dockerfile`** builds `recamera-build:latest` in two stages:
  - the first builds the riscv64/musl cross toolchain (GCC 15.3.0, C++ and OpenMP) with
    Buildroot 2026.05.3 and `container/sdk-defconfig`;
  - the second installs that SDK in `/opt/riscv64-musl`, over a Debian with Buildroot's
    dependencies.
- **Toolchain patches:** `container/patches/`, via `BR2_GLOBAL_PATCH_DIR`.
  - `gcc/15.3.0/0001-riscv-do-not-emit-fence-tso-by-default.patch`: GCC **does not emit
    `fence.tso`** by default.
  - **Why:** the SG2002's T-Head C906 core raises an illegal-instruction trap on
    `fence.tso`. GCC emits `fence rw,rw` instead, a stronger barrier, so memory ordering
    is kept.
  - `libstdc++` and `libgomp` come out that way too. Details in `docs/multimedia.md`,
    step 9.
- **Build it** (about 18 minutes):

  ```sh
  docker build -t recamera-build:latest container/
  ```

  Another image: `RECAMERA_BUILD_IMAGE=<image:tag> container/run.sh ...`.
- **`container/run.sh`:** mounts the tree at `/work`, runs as the caller's uid:gid with
  `HOME=/tmp`, and runs any command: `container/run.sh make all`,
  `container/run.sh sh -c '...'`.

## 3. Buildroot and the cache

```sh
container/run.sh make sg2002_recamera_emmc_defconfig   # first, and after changing the defconfig
container/run.sh make all                              # an explicit goal is required
```

- **Configuration:** `external/configs/sg2002_recamera_emmc_defconfig`, external
  toolchain (`/opt/riscv64-musl`).
- **No target U-Boot or OpenSBI is built:** the boot chain is the `fip.bin` of
  `recamera-fip`. Only the U-Boot tools are built (`host-uboot-tools`: `mkimage`,
  `mkenvimage`; `uboot-tools`: `fw_printenv`/`fw_setenv` on the camera).
- **ccache:**

  ```
  BR2_CCACHE=y
  BR2_CCACHE_DIR="$(BR2_EXTERNAL_RECAMERA_PATH)/../.ccache"
  BR2_CCACHE_INITIAL_SETUP="--max-size=20G"
  ```

  - The cache lives in the tree because the container runs with `HOME=/tmp`.
  - Turning ccache on or off, or changing the toolchain, needs a `make clean`.
  - Statistics: `container/run.sh sh -c 'CCACHE_DIR=/work/.ccache output/sg2002_recamera_emmc/host/bin/ccache -s'`.
  - Our CMake packages get ccache as a *launcher* (`CMAKE_<LANG>_COMPILER_LAUNCHER`),
    never inside `CMAKE_<LANG>_COMPILER`.

## 4. Scripts (`scripts/`)

| Script | What for | Runs on |
|---|---|---|
| `cam.sh ssh\|scp ...` | camera access (`RECAMERA_HOST`, default `192.168.42.1`; `RECAMERA_PASS`, default the image's documented password) | host |
| `slot-update.sh [a\|b] [--switch]` | writes the current build to the **inactive** eMMC slot, checks, resizes; `--switch` makes it the boot slot and reboots | host → camera |
| `write-sd-image.sh <img> /dev/sdX` | writes and checks the SD card: `pkexec bash "$PWD/scripts/write-sd-image.sh" "$PWD/output/sg2002_recamera_emmc/images/sdcard.img" /dev/sdX` (absolute paths, partitions unmounted) | host (root via `pkexec`) |
| `port.sh init\|add\|diff\|build <package>` | edits a Sophgo port in `work/<package>/` and regenerates its patch (§7) | host + container |
| `models.sh extract\|install [dir]` | extracts the 4 factory YOLO11n models (md5 checked) and installs them in the camera's `/data/models` | container + camera |
| `cvimodel-info.sh <model>` | inputs, outputs, pixel format and quantisation of a `.cvimodel` | container |
| `camdiag.sh` | a snapshot of the camera registers: `scripts/cam.sh ssh < scripts/camdiag.sh` | camera |
| `ion-measure.sh '<command>'` | samples the ION heap every 200 ms while a command runs | host → camera |
| `pack-emmc-pack.py`, `verify-cimg-pack.py` | the vendor USB-download eMMC pack (CIMG containers): build one, and check one before writing it | host |
| `serial/` | serial console helpers (USB-serial adapter on the camera UART) | host |

## 5. The `fip.bin` (package `recamera-fip`)

- The official Seeed fip (`fip-seeed-original.bin`) with **only its OpenSBI replaced** by
  the same Sophgo OpenSBI 0.9 plus the `fence.tso` emulation (Armbian's patch).
- **Checked in** as `external/package/recamera-fip/fip.bin` (sha256 `2db62808…`); the
  package checks the hash and installs it in `images/`, from where it goes into
  `sdcard.img` and the INSTALL set.
- `make-fip.sh` documents and reproduces it with the vendor SDK. It fails if:
  1. the unpatched OpenSBI it rebuilds is not identical to the official one;
  2. repacking the fip with it does not give the official fip back;
  3. the new fip changes anything besides the OpenSBI and its checksums.
- Writing it to the eMMC: the card's `emmc-install`, or by hand (boot0 at 0 and 1 MiB,
  boot1 at 0, each copy read back). See `docs/emmc-layout.md`.
- Why not a fip built from sources with mainline U-Boot: README, "Boot firmware".

## 6. The Rust application (`app/`, package `recamera-app`)

- **Toolchain:** Buildroot's Rust (`BR2_PACKAGE_HOST_RUST_BIN`, 1.96.1, target
  `riscv64gc-unknown-linux-musl`).
- **Dependencies:** vendored at build time through `dl/br-cargo-home` (network only when
  `Cargo.lock` changes). A new dependency or workspace member needs the lock updated
  first:

  ```sh
  container/run.sh sh -c 'export CARGO_HOME=/work/dl/br-cargo-home PATH=/work/output/sg2002_recamera_emmc/host/bin:$PATH; cd /work/app && cargo update --workspace'
  ```

- **Quick check on the host** (output outside `app/`, which the package's rsync would copy):

  ```sh
  container/run.sh sh -c 'export CARGO_HOME=/work/dl/br-cargo-home CARGO_TARGET_DIR=/work/work/app-target PATH=/work/output/sg2002_recamera_emmc/host/bin:$PATH; cd /work/app && cargo check --release'
  ```

- **For the camera:** `container/run.sh make recamera-app-rebuild all`. The build prints
  the size and the number of `fence.tso` of each binary (it must be 0).
- **Linking with the Sophgo libraries:**
  - `sophgo-sys/build.rs` links `librecamera-cam.a` (static, from `sophgo-mpi`, found by
    `rustc` in `$RECAMERA_SYSROOT/usr/lib`, which the package passes) and the MPI `.so`
    files (found by the linker in the sysroot). The list is `SOPHGO_MPI_CAM_LIBS`.
  - On the host (`cargo check`) nothing is linked: use `cargo check`, not `cargo build`.
  - A change in `recamera-cam.c` needs `make sophgo-mpi-dirclean recamera-app-dirclean all`.
- **Host tests** of the pure crates: `cargo test -p recamera-detect -p recamera-rtsp`.

## 7. When to rebuild what

| Changed | Command |
|---|---|
| the toolchain image, or `BR2_CCACHE` | `make clean`, `make sg2002_recamera_emmc_defconfig`, `make all` |
| the defconfig | `make sg2002_recamera_emmc_defconfig`, then `make <package>-dirclean` of what it touches, `make all` |
| a kernel patch or `linux.config` | `make linux-dirclean sophgo-ion-dirclean sophgo-osdrv-dirclean morse-driver-dirclean all` |
| the device tree only | `make linux-rebuild all` |
| a patch, `Kbuild` or `.mk` of a local package (`sophgo-*`, `recamera-*`) | `make <package>-dirclean all`: `-rebuild` re-applies the patches and fails with "duplicate filename" |
| the rootfs overlay | `make all`; a file **removed** from the overlay stays in `output/.../target` until `make clean` |

After a build: `scripts/slot-update.sh --switch`, test, then the same on the other slot so
both are equal.

## 8. Editing a Sophgo port (`scripts/port.sh`)

The vendor sources are never edited; each port is a patch series in
`external/package/<package>/`. With `RECAMERA_OS` pointing at a reCamera-OS 0.2.4 checkout
(with submodules):

```sh
scripts/port.sh init sophgo-osdrv          # work/sophgo-osdrv/a = vendor (+ earlier patches), b = a + the patch
scripts/port.sh add  sophgo-osdrv dwa/dwa.c # bring another vendor file into a/ and b/
# edit work/sophgo-osdrv/b/...
scripts/port.sh build sophgo-osdrv         # osdrv only: build the modules in the container (fast)
scripts/port.sh diff sophgo-osdrv          # regenerate the patch, check that the series applies
container/run.sh make sophgo-osdrv-dirclean all
```

- `a/` and `b/` hold only the files the patches touch (`cvi_mpi` alone is 283 MB).
- The regenerated patch has no timestamps: the same edit always gives the same patch.
- The patch header (author, description) is kept.

## 9. Site files (`local/`)

`local/` is ignored by git. `post-build.sh` installs `local/wpa_supplicant.conf`, when it
exists, over the public network-less one, so an image for your own camera joins your
Wi-Fi at the first boot. Without it, use the USB network (192.168.42.1) and the Network
page.

## 10. Known pitfalls

- **New kernel, old modules.**
  - Buildroot does **not** rebuild the `kernel-module` packages (`sophgo-ion`,
    `sophgo-osdrv`, `morse-driver`) when the kernel changes. A `linux.config` option can
    change the layout of kernel structs; the real case was `CONFIG_DETECT_HUNG_TASK`,
    which added `last_holder` to `struct semaphore`. The old `.ko` files still loaded and
    corrupted memory: an Oops in `vpu_open_instance`, encoder semaphores stuck.
  - **Rule:** after a kernel change, rebuild the three (table above).
  - **Guard:** `CONFIG_MODVERSIONS=y` makes the kernel refuse a mismatched module at load.
- **Built-in `make` rules.** A build from scratch failed in `host-e2fsprogs` and
  `host-xxhash` with `No rule to make target 'xxx.o'`: the top Makefile had
  `MAKEFLAGS += --no-builtin-rules`, inherited by every sub-make. It now has only
  `.SUFFIXES:`, which applies to itself. No global flags in `MAKEFLAGS`; a package that
  runs the `make` of another tree clears the environment
  (`env -u MAKEFLAGS -u MFLAGS -u MAKELEVEL`).
- **Implicit dependencies:** in a build from scratch the package order changes, and a
  dependency that "worked" by luck breaks. Declare every one.
- **Writing the SD card** needs root: use `pkexec` with `scripts/write-sd-image.sh`, never
  a hand-made `dd`. `pkexec` starts in `/`, so pass absolute paths, and unmount the card's
  partitions first (`udisksctl unmount -b /dev/sdX1`).
- **Booting from the card:** `S01data` does not mount the eMMC's `/data` (recovery mode).
  For tests mount it by hand: `mount -t ext4 -o noatime /dev/mmcblk0p4 /data`.
